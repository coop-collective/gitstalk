# Web baseline, 2026-10-11

Taken against staging https://gitstalk.dev before the performance work lands (build from origin/main at the time; staging as deployed). Raw data: [`baseline-2026-10-11.raw.json`](baseline-2026-10-11.raw.json) (every run), [`baseline-2026-10-11.bundle.json`](baseline-2026-10-11.bundle.json) (every file and per-page URL). Re-run with the steps in [`../README.md`](../README.md).

Conditions: headless Chrome for Testing (macOS, Apple silicon, home broadband, no throttling), 5 cold loads (new context = empty HTTP cache, shared socket pool) and 5 warm loads (same context, after one priming load) per route; 1.5 s settle after `load` so LCP is final. Test account `perf-<hex>` with one repo from the TypeScript starter, two beans and one Actions run (`ci.yml`). Numbers are single-location and noisy: staging TTFB moved by a few hundred ms between runs; the Actions run page was consistently the slowest route.

## Findings worth acting on

- The Actions run page has the worst TTFB by a wide margin: 2.5 s cold, 1.3 s warm, against 0.3 to 0.6 s for every other route (a smoke run showed 3.9 s).
- Every page ships about 640 KB raw (about 160 KB brotli) of JavaScript in 15 shared chunks, plus page chunks. A signed-in page loads 17 to 28 script/style assets named in its HTML.
- Home polls `/api/sessions` about every 3.3 s while visible (18 requests per 60 s) and stops when hidden. The repo Changes tab is silent when idle. The run page made a burst of 33 requests (a refresh plus prefetches of other routes) and still made 10 while hidden, so something on that page ignores visibility.
- A soft navigation to a repo tab issues 11 to 12 RSC requests (mostly link prefetches); browser back issues 11 RSC requests again and takes about 0.9 s, so back is a refetch, not a cache restore.
- Warm loads transfer 0 bytes of JS (chunks cached) but still make 50 to 70 requests; warm TTFB is the server cost.
- Signed-out `/` looks the same on both origins (53 KB JS, 10 requests); gitstalk.io was a little slower in 3 loads, which is not a conclusion.

## Method notes

- TTFB is navigation `responseStart`. LCP is the last `largest-contentful-paint` entry. JS transferred is `transferSize` of script resources (0 when served from cache); JS encoded is `encodedBodySize` (compressed size even when cached). Totals include HTML, CSS, fonts, images and fetches.
- "Hidden" is emulated by overriding `document.visibilityState` and `hidden`, dispatching `visibilitychange`, and bringing a second blank tab to the front. Headless Chrome may not report the real page as hidden, so hidden counts are an upper bound.
- Soft navigation: click on the tab link; "URL change" runs until `location` changes, "painted" until two animation frames after the later of the URL change and the last RSC request finishing. RSC counts include prefetches fired by the click and by links entering view.
- Bundle sizes come from `pnpm -F @gitstalk/web build` on this commit. gzip is level 9 and brotli quality 11 computed locally, so a lower bound on what the edge sends; per-page asset lists come from the live HTML.
- The `typescript-starter` template ships no workflow, so one (`.github/workflows/ci.yml`) was added in the first bean; the push triggered the run.
