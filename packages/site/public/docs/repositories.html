Repositories live

A repository belongs to a person, holds the sprout and the stalk, and runs its own engine: every bean pushed to it is checked, landed and validated without any other setup.

Create one

From New repository, give it a name, an optional description, and choose:

Start What you get
TypeScript starter (default) A small project with no dependencies: a module, its test (Node's test runner), a package.json, a README and .gitstalk/checks.toml. The first bean's check is real from the start.
Empty One commit with a README.
Import a public git URL Any public repository, for example https://github.com/fastify/fastify. Its history comes along; the sprout and stalk start at its default branch. A private URL comes back as an error on the form.

Names are unique per owner, ignoring case. If anything fails on the way, the half-made repository is removed and the name is free again.

The start page

Until the first bean, the repository page has one job: show exactly how to begin. It holds the clone URL, three ways to connect git (the plugin line, HTTPS with a token, or environment variables with a deploy token made on the spot), the sentence to hand to an agent, the six git commands that push a first bean, the files on the stalk, and What counts as green: the checks every bean must pass.

The repository tabs

Tab What it shows Status
Home The stalk, beans growing now, what happened recently, files, and the Ask box. Bean lines name the person who pushed them (last push @coop: add-truncate). live
Ask Type a question in plain words (what changed on coupons?) and the page reshapes around the answer: the files, their diffs, and the beans behind them. Live answers still take a few seconds. live
Settings Rename, description, visibility, deploy tokens, delete. live
Code Folders and files at the stalk, the sprout, any pushed bean or any commit, with syntax highlighting and a rendered README. live
Changes Beans in three lists: open (in check, red, conflict), landed, and parked. A bean's page shows its journey (each push, checks with failing tests, rework, landing, validation) and its diff, updating live. live
History The stalk's commits, and above them the sprout commits that landed but are not validated yet, with every validation verdict. live
People Who has access, and every session and token that cloned or pushed, with the person it acted for. See Collaborators. live
Archive The owner can archive a repository from Settings: reads and clones keep working, pushes are refused with one sentence. live
Insights, Automations Counts over time; the Actions and Automations list. coming soon

Every page works at night, by day and at phone width.

Settings and your profile live

Repository Settings and your own Settings share one layout: sections on the left, one panel each on the right, a save line under every form.

rolling out Every section of repository and organization Settings becomes its own page with its own Save, and archive, transfer, leave and delete move to a Danger zone page that asks before it acts. Old links to a section (…/settings#secrets) still land on it for anyone with a role on the repository; everyone else gets the not-found page. Your avatar in the header opens a menu with your profile, repositories, organizations, Settings, the day or night theme and Sign out.

  • Repository: name, description, website, topics and a social image (the picture link previews show), visibility, the default branch (always the stalk), checks, collaborators, Actions secrets, deploy tokens, archive and delete.
  • Your profile: a picture, name, bio and website, shown on your page (<gitstalk host>/<handle>), where anyone can also see your public repositories. Without a picture you get one made from your initials.
  • Pictures: PNG, JPEG, WebP or GIF (first frame), up to 2 MB and 4096 pixels a side. SVG is refused because it can carry scripts. Pictures are resized and stripped of camera and location data.
  • Handle: change it once a day. Your page, repositories and clone URLs move; links and git remotes with the old handle redirect, and nobody else can take it.
  • Access: passkeys (name them, add another, remove the last only once you have a verified email), signed-in browsers and connected agents, SSH keys and tokens. Emails: add or change the address that signs you in, verified by a code.
  • Delete your account: type your handle. Your repositories are deleted with it and you leave everyone else's. Notifications are not sent yet, so that page only says what is coming.

Renamed and moved live

When a repository is renamed or moved to another owner (you to an organization, an organization to you, or between organizations), its old address keeps working, so existing clones, CI and agent setups do not break:

  • Web pages at the old address redirect to the repository's home at the new one, the same as after a handle change.
  • Git over HTTPS and SSH: clone, fetch and push keep working at the old remote. Git does not follow a redirect on a push, so Gitstalk serves the old address in place instead. A push to it prints where the repository is now and the git remote set-url line to switch.
  • Agents: MCP tools that take owner/name accept the old one.
  • Renames chain: after a → b → c, both a and b lead to c. An old handle and an old name together still work.
  • The old address stops redirecting once someone creates a repository with exactly that owner and name, as on GitHub. Deleting the repository removes its old addresses.
  • An internal repository moved to a person becomes private: only organizations have internal repositories.

Organization handles cannot be changed yet.

Good to know

  • Storage is named by id, so renaming never moves git data.
  • Teams are not built yet.
