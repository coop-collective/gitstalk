Repositories live

A repository holds your code, a bean branch for every change in flight, and its own checking engine. Create one, push a bean, and it is checked and landed with no other setup.

Create one

Open New repository from the + New menu in the header. Pick an owner (you, or an organization that lets you create repositories), a name, an optional description and a visibility, then choose how it starts.

Start What you get
TypeScript starter A small library with no dependencies: a module, its test (Node's test runner), a package.json, a README and .gitstalk/checks.toml. The first bean is checked for real from the start.
Empty One commit with a README.
Import a public git repository Any public repository, for example https://github.com/fastify/fastify. Its default branch's history comes along and becomes the stalk. A private URL comes back as an error on the form: the message says it is not a public git repository (it asked for credentials or was not found).

Importing a private repository and two-way sync with another forge are planned.

The start page

Until the first bean lands, the repository page has one job: show exactly how to begin. Everything is copyable.

Connect git: three ways

Tab What it is for
Plugin The default. One line installs the Gitstalk plugin for Claude Code and runs /gitstalk:setup acme/api, which finds or makes an SSH key, asks you to approve it once in the browser and points git at the repository. Codex has its own line and a sentence to paste. See Connecting agents.
HTTPS Clone over HTTPS. When git asks for a password, paste a personal token with write access from Settings, Tokens; any user name works.
Env vars For CI and scripts: make a deploy token on the spot and copy a block that sets GITSTALK_TOKEN so git never prompts. The block needs git 2.31 or newer. Deploy tokens are made by an owner or a maintainer, and never on an archived repository. Settings, Deploy tokens shows the same block after the start page is gone.

Git remotes use HTTPS today

Registering an SSH key is live and approves your machine, but the remote it sets is an HTTPS URL. Git over SSH is built and not public yet. See Git compatibility.

The Code button

Once something has grown, the repository page opens on the Code tab, and the start page gives way to a Code button at the right of the bar above the files, where GitHub puts it. It opens a panel with three tabs; the last one you used opens next time. On a phone the panel is a sheet from the bottom of the screen. Escape or a click outside closes it.

Tab What it holds Status
Clone The HTTPS clone URL, SSH (live once the deployment serves it), a git clone line and git push origin HEAD:bean/<name>, each with a copy button. Below them: where git's password comes from (a personal token from Settings, Tokens) and, for owners and maintainers, a link to Settings, Deploy tokens for CI. Without JavaScript the button still opens this tab. live
Agent Claude Code, Codex, Cursor, Gemini CLI and any other MCP client, one tab each, with the lines that connect that agent to this repository and what to ask it next. For Claude Code that is the plugin plus /gitstalk:setup acme/api. The harness you pick is shared with the install page. Links to the plugin and to Connecting agents. live
Submit intent Describe what you want, and Gitstalk opens a bean with your intent for an agent to pick up. Shown, but not working yet. planned

A tour of the tabs

Every repository has the same seven tabs. Everyone who may see the repository sees the tabs; the Settings tab shows for people with a role.

Tab What it shows Status
Code The front page. Folders and files at the stalk, the sprout, any pushed bean or any commit, with syntax highlighting and a rendered README. A side column shows the description and how many beans are on the stalk; the Code button clones it or connects an agent. Before the first bean it is the start page above. live
Changes Beans in three lists: open (in check, red, conflict, waiting), landed and parked. A bean's page tells its journey: each push, the pre-land check with its failing tests, rework, landing, validation and any decision card. The list updates live. live
History The stalk's commits, and above them the sprout commits that landed but are not validated yet, with every validation verdict. live
Automations One tab, two views: Actions (your .github/workflows and their runs) and Automations (agents and scripts in .gitstalk/automations). See GitHub Actions and Automations. live
Ask Type a question in plain words (what changed on coupons?) and the page reshapes around the answer: the files, their diffs and the beans behind them. Live answers still take a few seconds. live
People Who has access, and every session and token that cloned or pushed. See Collaborators and visibility. live
Settings One page per section, from General to Danger zone. See the Settings map. live
Insights Landing rate, waiting time and rework per person and agent. planned

There is no separate Home or Stalk tab. The old Stalk address redirects to History. The pages work at night, by day and at phone width.

Reading History

Renamed and moved

live When a repository is renamed or moved to another owner (you to an organization, an organization to you, or between organizations), its old address keeps working, so existing clones, CI and agent setups do not break.

Where What happens at the old address
Web Pages redirect to the repository's home at the new address.
Git Clone, fetch and push keep working at the old remote. Git does not follow a redirect on a push, so the old address is served in place. A push there prints where the repository is now and the line to switch.
Agents MCP tools that take owner/name accept the old name.
  • Renames chain: after a to b to c, both a and b lead to c. An old handle and an old name together still work.
  • An old address stops redirecting once someone creates a repository with exactly that owner and name, as on GitHub. Deleting the repository removes its old addresses.
  • An internal repository moved to a person becomes private, because only organizations have internal repositories.

Archive, transfer, delete

These live in Settings, Danger zone, which the owner sees. Each asks before it acts.

Action What it does
Archive Makes it read-only: reads and clones keep working, while pushes, decision answers, deploy tokens, workflow runs and Actions secret changes are refused, and it leaves Home. Name, description and visibility are fixed until you unarchive.
Transfer Moves it, with its history, beans, collaborators and deploy tokens. The old address keeps working (above).
Delete Removes its history, beans and decisions for good. Agents connected to it lose access at once.

Renaming, the description and the social image are in Settings, where profile and upload details also live.

Good to know

  • Storage is named by id, so renaming never moves git data.
  • Teams are not built yet (planned). Give access person by person or through an organization.
  • Organization handles cannot be changed yet.
