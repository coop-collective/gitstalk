Approval rules beta

Let comment-only and docs changes land on their own, and send risky paths to a person. One file on your stalk, .gitstalk/policy.yml, says which kinds of change land by themselves, which a small model triages, and which wait for a human.

Beta

Merged on 14 October 2026. The code is in the repository; whether the hosted service already runs it was not confirmed when this page was written. A few pieces are not built yet, listed at the bottom.

Try it

  1. Open Settings, Approval rules

    Owners and maintainers edit. Everyone else with a role can read the file and sees why they cannot save.

  2. Write a rule

    The editor checks your YAML as you type, with the same parser the engine runs, so the messages and line numbers match.

  3. Save

    Saving pushes a bean with you as its author. It lands through the pre-land check like any change, and the rules apply once the stalk takes it.

The file

.gitstalk/policy.yml
# yaml-language-server: $schema=https://gitstalk.dev/schemas/policy.json
groups:
  security: ["@alice", "@bob"]
classes:
  - name: comment-only
    match: { syntax: comments-and-whitespace }
    route: auto
  - name: docs
    match: { class: docs-only }
    route: auto
  - name: migration
    match: { paths: ["src/db/migrations/**"] }
    route: card
    reviewers: ["@data"]
  - name: protected
    match: { paths: ["src/auth/**"] }
    route: card
    writers: ["@security"]
  - name: api
    match: { paths: ["src/api/**"] }
    route: triage
Key Meaning
groups Names for lists of people: security: ["@alice", "@bob"].
classes[].name Lower-case letters, digits and dashes, unique. policy-change is built in.
match One of { paths: [...] } (any changed file matches a pattern; the patterns are the same as protected paths), { syntax: comments-and-whitespace } (every changed file differs only in comments and whitespace), or { class: docs-only | tests-only | lockfile | comment-only } (a built-in class).
route auto, triage or card (below).
reviewers Who the card is addressed to. Shown, not enforced yet.
writers The only principals who may change this class (below).

Parsing is strict: YAML 1.2 (so no stays a string), unique keys, and no anchors, aliases or merge keys. A file that is invalid on the stalk leaves only the built-in rules in force, and the push says so. With no policy file at all, every bean is auto and pushes show no rules lines, exactly as before.

Classes

A class is a kind of change. Classes are computed by code from the changed paths and the file contents, never by a model.

Built-in class Holds when every changed file is
docs-only *.md, *.mdx, *.markdown, *.txt, *.rst, *.adoc, or under docs/
tests-only under test/, tests/, __tests__/, or named *.test.*, *.spec.*, *_test.*, test_*.py
lockfile a package manager's lockfile
comment-only unchanged in code: only comments and whitespace differ (below)

How comment-only is judged

Each side of each changed file is read into code tokens with comments and whitespace dropped; the two streams must be equal. Strings, template literals, regular expressions and Rust raw strings stay whole. It is judged for TypeScript and JavaScript (not JSX), Rust, C and C++, Java and Go. Every doubt means not comment-only: an added, deleted, binary or unknown file, anything unterminated, or a file over 512 KB. A reformat such as )+( to ) + ( counts as code.

policy-change

Any change under .gitstalk/ (except backlog.md, which agents tick with ordinary beans) is a policy-change. From an agent it is always a card, whatever the file says. When it is a person's own push and they may decide (an owner or maintainer with a personal token or SSH key, or the Settings editor), the push is the decision and the other classes route it. The policy file is also always a protected path.

Routes

  1. Classifypaths and syntax
  2. Autoland on its tests
  3. TriageClef picks auto or card
  4. Cardheld for a person

When several classes match, the strictest route wins: card over triage over auto. A comment-only change takes the route of your comment-only class when you have one, even inside a sensitive path, because no behaviour changed.

Route What happens
auto The bean lands and promotes as usual, on its tests.
triage Clef, a small model that only sees class names and paths (never contents), picks auto or card within 2.5 seconds. If it is late or unavailable, fixed rules decide: auto when the bean is also comment-only, docs-only or tests-only, otherwise card. Clef holds a bean only when it is at least 65% sure a card is needed; a less certain card lands on its tests.
card Held before landing until a person approves. The check answers a red, awaits approval by a person, that says nothing needs fixing. The approval is for that exact revision; a new push needs a new approval.

Clef and Jev only pick or rank. They never write code. The receipt names the model that decided.

Writers

writers limits who may change a class. A bean from a principal outside the list falls off at the pre-land check, the same way a protected path does, naming the classes and who may change them.

Principal Means
@handle A person: any push acting for them, by any credential.
@group A name under groups. A group wins over a handle of the same name.
agent:a<slot> An agent slot in a benchmark race. Not used for ordinary repositories.

Receipts

Every judged bean leaves a receipt: its classes, the route, which class decided, who decided (policy, clef or rules), Clef's probability, the approval state, and the policy file and stalk commit it was judged by. The push prints it on its remote lines, and the MCP bean_status tool reports the route and a next step when a bean is held.

Where the rules are read from

Always from the stalk, never from the bean being judged. A bean cannot change the rules that judge it. If the stalk cannot be read, the check is retried; it is never treated as "no policy".

Not done yet

  • No approve button in the web. Approvals go through a gateway call (approveBean); there is no button on the bean page and no MCP tool yet. Until one ships, a card route is best read as a stop sign, not a workflow.
  • reviewers are shown, not enforced: any person who may decide approves.
  • The bean view in the web has no approval-rules label yet; the receipt is on the push lines and in bean_status.
  • Clef's answers are not yet compared with later human decisions.
