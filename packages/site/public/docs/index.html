Gitstalk docs

Gitstalk is an agent-first git forge. Many coding agents push small changes to one codebase at once, and each change lands as soon as it passes its tests on the exact tree it would land on. Nobody waits in a merge queue, and the stable line only ever holds verified work.

Three words

  • A bean is one change: a branch named bean/<name>, pushed by an agent or a person.
  • The sprout is the staged line. A bean lands there once its pre-land check passes on the sprout plus the bean.
  • The stalk is the stable line. It moves only to sprout commits that passed validation, so it is always green.

Who it is for

Teams that run several coding agents (Claude Code, Codex, Cursor or others) on the same repository and spend their time on merge queues, rebases and broken main branches. It also works for people: a bean is just a git push.

Getting started

About a minute, with Claude Code and git installed.

  1. Sign up

    Sign up with a handle and a passkey. No password, no email needed.

  2. Create a repository

    Choose New repository. Start from the TypeScript starter (a small project with tests), an empty repository, or import any public git URL.

  3. Install the plugin and connect git

    One line installs the Claude Code plugin and connects git to your account:

    claude plugin marketplace add coop-collective/gitstalk-plugin && claude plugin install gitstalk@gitstalk && claude "/gitstalk:setup <owner>/<repo>"

    /gitstalk:setup picks an SSH key on your machine (or makes one), opens a Gitstalk tab for you to approve it, and points git at your repository. Other agents: Connecting agents.

  4. Push a bean

    git switch -c work origin/sprout
# change something, with a test
git commit -am "Add a truncate helper"
git push -o wait origin HEAD:refs/heads/bean/add-truncate

    The push prints the verdict when the check ends:

    remote: gitstalk: pre-land check started: your change is merged onto the sprout and the whole suite runs on that tree
remote: gitstalk: LANDED: add-truncate passed its pre-land check and is on the sprout
remote: gitstalk: validated: on the stalk

    On the hosted service this took about 17 seconds end to end for a small repository. Or just ask your agent to do the work: the plugin's skill teaches it the flow.

What is in it

Every page says what is live on the hosted service, what is rolling out (built and verified on a staging copy, not yet on the hosted service) and what is coming soon.

  • RepositoriesliveCreate, import, the start page and the repository tabs.
  • Git compatibilitylivePlain git: bean/* branches, push options, verdicts on the push, status refs.
  • Connecting agentsliveThe plugin, SSH keys and tokens, containers, MCP and OAuth.
  • Checkslive.gitstalk/checks.toml: what a bean must pass, and protected paths.
  • Collaborators and visibilityliveRoles, invitations, public and private repositories, organizations, internal repositories.
  • Decision cards and reconcileliveWhen two changes truly disagree, a person decides.
  • Streaming diffscoming soonWatch a bean's change arrive while its agent writes it.
  • GitHub ActionsliveYour .github/workflows, run on Cloudflare.
  • AutomationsliveAgents defined in git that react to Gitstalk events, with their own memory.
  • Self-hostingliveRun all of Gitstalk on your own Cloudflare account.

How it works, and how we know

Architecture explains the engine and the Cloudflare pieces, with the measured results: against GitHub's own merge queue on 38 real changes from fastify, Gitstalk integrated each change 6–9× faster with 16 parallel workers. What did not work lists the ideas we measured and dropped.
