Git compatibility live

Git is the interface. Pushing a bean/<name> branch submits a change; the verdict comes back on the push and as a ref anyone can fetch. Nothing is installed on the client beyond a credential.

URLs

A repository is cloned from the web host, where its page is, with a GitHub-style URL (the .git suffix optional); the repository page shows it: 

git clone https://<host>/<owner>/<repo>.git

The older gateway URL, https://<gateway host>/git/<owner>/<repo>.git, keeps working.

A repository you may not see answers 404, exactly as a missing one does. Public SSH remotes (ssh://git@<ssh host>/<owner>/<repo>.git) are coming soon: SSH on port 22 needs a paid Cloudflare plan (Spectrum), so it is not offered yet. HTTPS clone and push work today, and /gitstalk:setup stores an HTTPS token for you.

Push is submit

You push What happens
refs/heads/bean/<name>, a new name A new bean. Its title is the commit subject, its intent the message. A Task: <id> trailer links a task.
the same bean after a red or a conflict The fix: the new head is checked again. Force-push after a rebase is expected.
a new commit to a bean still in check Refused: its verdict comes first. The message says how to wait for it.
a bean that already landed Refused: push new work as a new bean.
sprout, stalk, main Refused: landing is never a push. Only the engine moves these lines.
any other ref, a deletion, two beans at once Refused, with the rule.

Refusals happen inside the git protocol, before anything reaches storage, so git prints a normal ! [remote rejected] line with the reason rather than an HTTP error.

Push options

Option Effect
-o wait Hold the push until the verdict: landed, red, conflict, parked or dropped. Progress lines as the engine reports them and a keepalive every 15 s; gives up after 600 s and says where the verdict will be.
-o wait=<seconds> The same, up to 1,800 s.
-o task=<id> Links a task (overrides the trailer).
-o intent=<text> The bean's intent and title, instead of the commit message.
-o bean=<name> On a push to a wait ref (below): a bean to wait for. Repeat it for several.

A plain git push without options returns as soon as the bean is received. That is the recommended flow for agents: push, take the next task, and read the verdict later.

What the push prints

Every line starts remote: gitstalk:. A red names what broke and why:

RED: tax-in-total was not landed. Merged onto the sprout, these tests failed:
  - test/discount.test.js
it collided with these landed beans (accepted behaviour; keep both):
  - add-discount "Add percentage discounts"
    intent: discounted(items, rate) takes rate off the cart total.
fix: git fetch origin sprout && git rebase origin/sprout
     then fix, commit and git push -f origin HEAD:refs/heads/bean/tax-in-total

A conflict quotes up to four conflicting hunks, both sides, and who landed the sprout's side.

Status refs

Ref What
refs/heads/sprout The staged line: every landed bean.
refs/heads/stalk The stable line: validated sprout commits.
refs/heads/bean/<name> The bean's pushed head.
refs/beans/<name>/status An annotated tag: <phase>: <reason>, then the verdict's lines. Phases: checking, red, conflict, landed, green, parked, dropped. 
git fetch origin '+refs/beans/*:refs/beans/*'
git for-each-ref 'refs/beans/' --format='%(refname:lstrip=2) %(contents:subject)'
git cat-file -p refs/beans/add-total/status

Waiting without polling

An agent that has pushed several beans and run out of work makes one blocking call that the first verdict wakes. A push to a wait ref stores nothing: 

git push -o bean=a -o bean=b origin HEAD:refs/wait/any   # returns at the first verdict
git push -o bean=a -o bean=b origin HEAD:refs/wait/all   # returns when none is checking
git push origin HEAD:refs/wait/all                       # every bean in flight pushed with my credential

It holds up to 9 minutes by default, under the 10-minute limit of an agent's shell tool, and prints each verdict as it arrives. -o wait and MCP bean_wait use the same wait: the verdict wakes them, nothing polls. Why it exists: agents replaced blocking pushes with sleep loops.

Importing and leaving

Any public git URL can be imported when you create a repository. Importing a private repository and two-way sync with another forge are coming soon. Your history stays plain git: clone it, and push it anywhere else. Branch names other than bean/*, sprout and stalk are not accepted on push today, and tag pushes are refused.
