Self-hosting live

All of Gitstalk's source is public, and the whole forge deploys to one Cloudflare account with two commands: one creates what an environment needs, one deploys it. Run staging and production side by side. You set the limits.

What you need

  • Node 24 or later, pnpm 11, stable Rust, and Docker (it builds the container images).
  • A Cloudflare account on Workers Paid, with Containers, Durable Objects and Artifacts, and Workers AI for Ask.

Deploy

The repository holds no account's ids. Each package's wrangler.jsonc is a template, and each deployment you run is an environment: one directory, environments/<name>/, with your account, a name suffix and the packages to run. 

pnpm install
pnpm check                                   # format, lint, typecheck, tests
npx wrangler login
npx wrangler whoami                          # your account id
cp -r environments/example environments/staging
# edit environments/staging/env.jsonc: account_id, workers_dev_subdomain
pnpm env:provision staging                   # create resources, secrets, migrate D1
pnpm env:deploy staging                      # --dry-run checks without uploading

env:provision creates what the environment needs if it is missing (D1 databases, the OAuth KV namespace, R2 buckets, the repository-events queue), writes their ids to environments/staging/resources.json, generates the Workers' secrets into environments/staging/secrets/ (never printed, never committed) and applies the D1 migrations. Artifacts namespaces are created by the first repository. Run it again after an update that adds a resource or a migration.

env:deploy writes each package's config for the environment, stops if a required secret is missing, then deploys the Actions executor, the gateway with its runner container, the MCP server, the site, the web app and SSH, in that order. Every Worker and resource is named <prefix>-<name><suffix>: the prefix defaults to gitstalk, and with the suffix -staging you get gitstalk-gateway-staging and gitstalk-forge-staging. An empty suffix keeps the base names. An emergency stop for everything: POST /v1/admin/halt with the admin token.

Your own domains

Without urls, every Worker answers on its workers.dev address. To use your own hostnames, put the zone in the same Cloudflare account and name one origin per package in env.jsonc. Each becomes a Workers Custom Domain of that Worker (Cloudflare creates the DNS record and the certificate on deploy), and every address the code prints follows: clone URLs, the MCP URL, the docs link, the OAuth and Actions OIDC issuers. 

"urls": {
  "web": "https://git.example.com",       # the app, and git: https://git.example.com/<owner>/<repo>.git
  "site": "https://git.example.com",      # same origin: the web serves the site's pages
  "mcp": "https://mcp.git.example.com",   # agents connect to /mcp
  "gateway": "https://api.git.example.com", # Actions jobs and the OIDC issuer /_actions/oidc
  "ssh": "https://ssh.git.example.com"
}

When site and web share an origin, the web app hands the site's paths to the site Worker over a service binding: /docs/, the site's files and pages, and / for someone signed out. Passkeys belong to the web app's hostname, so pick it before people sign up. Git over SSH on port 22 needs Spectrum, which a zone on the Free plan does not have; without it, leave SSH_TUNNEL on and people use HTTPS.

Search engines stay out unless you say otherwise: every environment answers /robots.txt with Disallow: / and marks its pages X-Robots-Tag: noindex, so staging and test stacks never show up in results. For the one deployment that should be found, set "search_indexing": true in its env.jsonc: its robots.txt then keeps crawlers out of only the app's private areas and names /sitemap.xml, which lists the landing, these docs and the sign-up pages on that deployment's own origin.

Secrets each Worker needs

Worker Required secrets
Gateway ADMIN_TOKEN, RUN_TOKEN_SECRET, ACTIONS_SECRETS_KEY, OIDC_REQUEST_SECRET, OIDC_SIGNING_KEYS
Actions executor ADMIN_TOKEN
Web app DEMO_PASSWORD (optional: TURNSTILE_SECRET_KEY)
SSH SSH_HOST_KEY
MCP server, site none

A secret already set on the Worker counts. Provision never replaces a secret a Worker already has: a new ACTIONS_SECRETS_KEY would make every stored Actions secret unreadable, so keep a backup of secrets/. pnpm env:secrets staging pushes the values to the Workers (they are never printed). For CI, store them once from your machine as the GitHub environment secret GITSTALK_SECRETS_JSON: 

pnpm env:secrets staging --to-github <owner>/<private repository>

Keep your environments in a private fork

The public repository ignores environments/ except the example. Keep yours in a private repository with the public one as upstream: 

git clone https://github.com/coop-collective/gitstalk.git my-gitstalk
cd my-gitstalk
git remote rename origin upstream
git remote add origin <your private repository>
git checkout -b main
git add -f environments/staging/env.jsonc environments/staging/resources.json
git commit -m "environments: staging"
git push -u origin main

git fetch upstream && git merge upstream/prototype   # later: stay in sync

Your fork only adds files under environments/, which upstream never writes, so the merge does not conflict. Never add secrets/. A scheduled workflow can do the merge for you: fetch upstream, merge (a pull request when it conflicts), push.

The deploy workflow in .github/workflows/ deploys staging on every push to main, and production only when you run it by hand or push a production-* tag, through the GitHub environment production, where you can require a reviewer. Each run checks the code, provisions, pushes the secrets, deploys and smoke-tests. It does nothing in a repository without environments/<name>/env.jsonc. Each GitHub environment (staging, production) needs two secrets:

  • CLOUDFLARE_API_TOKEN: an account token with edit on Workers Scripts, D1, Workers KV Storage, Workers R2 Storage, Queues, Containers, Artifacts and AI Gateway, read on Account Settings, and for your zones edit on Workers Routes, DNS and SSL and Certificates, read on Zone.
  • GITSTALK_SECRETS_JSON: set with env:secrets --to-github.

What it runs on

Piece Cloudflare product
Gateway: git proxy, engine, registry, repository RPC Workers, Durable Objects (SQLite)
Runner: squash, merge, revert, run the suite Containers (Rust, standard-4)
Git storage Artifacts
Accounts, repositories, access, the activity index D1
OAuth grants KV
Repository events to the index Queues
Actions logs R2
Web app (Next.js App Router on vinext) Workers
MCP server Workers, Workers AI
SSH (when enabled) Workers, Durable Objects, Containers, Spectrum

Limits you set

Setting Default Where
Pre-land checks at once per repository (one sandbox each) 32 (1–64) repository engine setting preland_sandboxes
Validations at once 2 (1–16) ci_slots
Runner containers in the shared pool 48 max_instances and RUNNER_MAX_INSTANCES in the gateway's config
Suite time limit 300 s timeout_seconds in checks.toml
Actions minutes per repository per month 100 ACTIONS_MONTHLY_MINUTES
Actions job timeout 60 min ACTIONS_JOB_TIMEOUT_MINUTES
Concurrent Actions jobs 4 ACTIONS_CONCURRENT_JOBS

Run a race against your own deployment

The race harness reproduces the published numbers on your account. Replay agents cost nothing; real agents need the claude CLI. Each race deletes its repository when it ends and prints its infrastructure cost, about $0.40 per 30-agent Gitstalk race in our runs. Commands are in the README.
