Checks live

One file, .gitstalk/checks.toml, says what every bean must pass. It is read from the exact tree each check runs on, so a change to the checks is checked by its own copy.

A repository without the file, or with the starter's older [[check]] draft, runs the default suite: node --test with a 300-second limit. The push says which one ran.

Gitstalk was called Beanstalk until 10 October 2026. A repository that keeps its checks in .beanstalk/checks.toml still works: that file is read when there is no .gitstalk/checks.toml, and is protected the same way.

The file

# .gitstalk/checks.toml
image = "node"
command = ["node", "--test", "spec/**/*.spec.mjs"]
timeout_seconds = 60
protected_paths = ["data/schema.json", "migrations/**"]

[env]
KV_LIMIT = "3"
Key Default Rules
image "node" Only node today (Node 25). Other languages need their own runner image; not built yet.
command ["node", "--test"] An argv, never a shell (so not npm test). Must start with node and include --test; the rest are options and test globs.
timeout_seconds 300 1 to 1,800. A suite that runs out of time is run again, and is never reported as red.
protected_paths [] Patterns: * within a segment, ** across segments, a trailing / for a directory. .gitstalk/checks.toml is always protected.
[env] none Up to 32 upper-case names; the runner's own (PATH, HOME, CI, GIT_*…) are refused.

Unknown keys are refused by name (unknown key "comand" (did you mean "command"?)). Suites run offline with nothing installed at check time, so today only zero-dependency projects work; a cached install step keyed by the lockfile is not designed yet.

What the push says

The tree has The check
no file The default suite, and the push says so.
a valid file Its command, environment and time limit.
an invalid file Red without running anything, naming every problem with its line and column.

Protected paths

A bean that changes a protected path is red before any test runs, unless it was pushed by the owner or a maintainer with their own personal token or SSH key. Agent sessions and deploy tokens never may, whoever they act for. The patterns come from the sprout's copy of the file, so a bean cannot unprotect itself. This is how an agent is kept from weakening the checks it is judged by. 

gitstalk: changes protected paths (data/schema.json): refused for a deploy token acting for @coop
gitstalk: RED: schema was not landed.

The landed beans' acceptance tests are protected in races the same way. For pushed beans, the whole suite is the check.
