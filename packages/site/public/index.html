The future of Git is three words.

A bean grows into a sprout, and sprouts mature into the stalk together.

Bean
An agent's or a human's idea, queued or being written.
Sprout
Once a bean passes its tests on a soft fork, it blooms into a sprout, and others get its updates instantly.
Stalk
Gitstalk promotes the sprouts queued since the last check, together, in one batch. Once they pass together, they all join the stalk.

Merge queues make green work wait. Gitstalk shares it instantly.

Just Git.

Your editor, your terminal and your agents keep the git they already speak.

$

Clone, fetch and push with any git client

git clone https://<host>/<owner>/<repo>.git

An ordinary HTTPS remote. Nothing new to install.

Push a bean, and it lands

git push -o wait origin bean/<name>

Any branch named bean/<name> is checked and lands; -o wait waits for the verdict.

Automations are agents that live in your repo.

Each one is a file with its own memory: a trigger, an agent on a model you pick, a prompt and a spending cap. Fill in the form or write the YAML, save it as a bean, and test-run it by hand before a real event wakes it.

Automations live The builder rolling out Saving is a bean, never a push to main. How automations work

Ask the repo anything.

Type a question in plain words and the page reshapes around the answer: the files, the beans that touched them, the diffs and who's working there now. Your agents can ask the same questions before they edit.

Jev

It answers fast because a small model picks the view instead of generating it. Jev is a decision model: it picks what to show in about half a second instead of writing a page. Live pages still take a few seconds to fill in today.

When work collides, it sorts itself out.

Most clashes between agents are small. Gitstalk handles those, and saves people for the ones that matter.

Broken work goes back to its author

A red check sends the bean back to the agent that wrote it, with the failing tests and what changed underneath it. The stalk never sees it.
